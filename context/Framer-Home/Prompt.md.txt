### Known Runtime Limitations & Workarounds

Some integration issues live in the upstream Framer runtime that ships
with this export. Apply the workarounds below for any limitation that
affects the component(s) you're integrating. Each only applies if the
bundle actually triggers it (so all entries here are confirmed
relevant for THIS export).

**Do not wrap Framer exports in `React.StrictMode`.**

The bundled framer-motion runtime stores init state in module-scope
variables and is not idempotent across mounts. React.StrictMode in
development double-invokes every mount (mount → unmount → mount). On
the second mount, the runtime sees its state already populated and
throws:

```
Error: mix Motion versions undefined with 11.18.2
```

Most modern React templates (Vite default, Next.js default, CRA)
enable StrictMode at the root by default. If you copy a template
verbatim, you'll hit this on first render with no obvious clue what
caused it.

Two ways to handle it:

1. **Remove StrictMode entirely** for projects whose only purpose
   is rendering Framer exports. Edit `main.tsx` / `layout.tsx`
   and drop the wrapper.

2. **Hoist StrictMode above the Framer route only.** If you want
   StrictMode for the rest of your app, mount the Framer-bearing
   route outside the StrictMode boundary — e.g. render
   `<App />` inside StrictMode but render `<ButtonIconPage />`
   outside it.

This is production-safe either way (StrictMode is dev-only — it has
no effect on the production bundle).

---

**If using Vite, exclude the Framer bundle from React Fast Refresh.**

The Framer bundle is a single large file with mutual component
references (`withFX(motion.div)`, variant maps referencing variant
maps, etc.). On first save, Vite's Fast Refresh tries to fingerprint
the changed module via `react-refresh`'s `computeFullKey` — which
walks references recursively, never terminates on this shape, and
overflows the call stack:

```
RangeError: Maximum call stack size exceeded
  at computeFullKey ...
```

The exception is fatal to the dev server's HMR loop until the page
is force-reloaded.

Fix in `vite.config.ts`:

```ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [
    react({
      exclude: [
        /_framer-runtime\.js$/,
        /\/components\/[A-Z][^/]*\.js$/, // any precompiled Framer bundle
      ],
    }),
  ],
});
```

Excluded files do a **full page reload** instead of in-place
hot-swap on change. You'd never edit a vendor bundle anyway, so
the trade-off is free.

(Next.js consumers can ignore this section — Next.js uses its own
HMR pipeline that doesn't hit this bug.)

**Component must be imported via `next/dynamic({ ssr: false })` (or framework equivalent).**

This export depends on framer-motion's gesture / scroll / loop / appear
runtime, which reads `window` / `document` / `matchMedia` /
`IntersectionObserver` at module-init time. Importing it directly into
a server-rendered route will fail at build with `ReferenceError: window
is not defined`.

**Important:** the Next.js `"use client"` directive alone does NOT fix
this. `"use client"` marks a component as client-rendered after
hydration, but Next.js still pre-renders Client Components during the
initial SSR pass — that pre-render is where the throw happens. Only
`next/dynamic({ ssr: false })` actually skips the pre-render.

Next.js (App Router):

```tsx
import dynamic from 'next/dynamic';

const ButtonIcon = dynamic(() => import('./components/ButtonIcon'), { ssr: false });

export default function Page() {
  return <ButtonIcon />;
}
```

Other frameworks: use the equivalent client-only import wrapper
(Remix `<ClientOnly>`, Astro `client:only`, vanilla React with a
`useEffect` mount gate, etc.).

Components in this export that do NOT trigger this requirement can be
imported normally. Only the ones with hover/gesture, scroll, loop, or
appear behavior need the dynamic wrapper.

**`__withFX` React warning is a diagnostic signal, not noise.**

If the dev console emits `React does not recognize the __withFX prop`

---

**Animations don't fire (Loop, Scroll Transform, Appear).**

Bundled components carry every animation spec they need on `__framer__*`
props but the runtime drops them on the floor. Build a centralized
client component (e.g. `FramerEffects.tsx`) that mounts once at the
page root and runs the animations the bundle declares but doesn't
execute. Discovery loop per component:

1. Grep the bundle for `__framer__loop`, `__framer__transformTrigger`,
   `__framer__styleAppearEffectEnabled`, `__framer__presenceInitial`,
   `__framer__animate`, `__framer__enter`.
2. For each match, find the target's class name (the motion node it's
   attached to) and the referenced transition/animation vars
   (`transition2`, `animation`, `__framer__spring`, etc.).
3. Extract the spec: physics spring (`stiffness/damping/mass`),
   duration spring (`duration/bounce`), or bezier tween
   (`duration/ease`).
4. Add a `RevealSpec` / `LoopSpec` entry pointing at the selector
   with the extracted spec.

Execution rules that matter:

- Use **WAAPI** (`element.animate(...)`). framer-motion writes `transform`
  to inline style every frame and will clobber CSS keyframes/transitions
  on the same property.
- For springs, pre-sample to keyframes matching framer-motion's physics
  — don't approximate with cubic-bezier. Long springs visibly differ.
- For in-view triggers, `IntersectionObserver` with `threshold: 0`
  and `rootMargin: "0px"` is the closest match to Framer's
  "Layer in View". For appear-once, store a `Set<Element>` of fired
  targets so reveals don't re-run on scroll-out.
- For opacity reveals, always treat as fire-once even if the bundle
  doesn't request it — scrolling past and back otherwise makes whole
  sections vanish.
- For loops with `__framer__loopPauseOffscreen: true`, gate
  `play()/pause()` on an IntersectionObserver entry — rotating rings
  off-screen burn battery.
- Initialize each target at the from-state immediately (paused WAAPI
  animation pinned at frame 0) before IO fires, otherwise there's a
  one-frame flash at the natural rest position.

---

**Bundle variable names are lexical, not semantic.**

When reimplementing effects (above), do NOT assume `transition1` is
the variant transition because it's at the top of the file. Always
follow the prop chain: find the `__framer__spring` / `__framer__transition`
on the specific motion node, walk to the var it references, read the
shape.

When reading a spring spec:

- Check `durationBasedSpring` first. If `false` (the common case),
  only `stiffness` / `damping` / `mass` matter; ignore `duration` /
  `bounce` even though they're present in the spec.
- For duration-based springs, framer-motion's mapping is non-obvious —
  read its source rather than approximating.

Inline `transform: translateY(...)` shown in devtools is often stale
— WAAPI updates pixels on a different layer. Trust pixels, not the
inline style attribute.

---

**Hover/gesture variants animate poorly.**

Rules of thumb when overriding hover behavior on exported components:

1. **Key hover CSS on the variant class, never `data-framer-name`.**
   For every `*-hover` gesture, the bundle emits
   `addPropertyOverrides({ "X-hover": { "data-framer-name": void 0 } })`
   — the attribute is removed mid-gesture. Use the variant class
   (e.g. `.framer-v-12dzqzc`) which persists.
2. **For mutually-exclusive variant elements that mount/unmount on
   hover** (e.g. `isDisplayed1`-gated nodes), hide the export's
   version with `display: none` and render persistent labels via
   your own client wrapper. Mount/unmount on every cursor move kills
   framerate.
3. **For `backdrop-filter` tweens between values** — browsers don't
   interpolate it cleanly. Set a single static value via CSS and let
   opacity carry any visual change.
4. **For width/flex deltas on hover that force layout reflow** — pin
   the indicator's width via CSS to its rest value. The button's
   color/border-radius transitions still play; only the layout-shift
   dance is suppressed.

---

**Variant style overrides don't propagate to nested elements.**

The bundle's per-variant config specifies different colors / opacity /
positions for nested elements per variant, but the runtime applies
none of them. Solid Black buttons render with default-dark text on a
dark background (invisible). FAQ "Open" variant leaves the answer at
`opacity: 0; position: absolute` from the closed state.

For each broken per-variant style:

1. Open the bundle, find the `variants: { variantId: { ...overrides } }`
   block on the affected element. Note the intended value for each variant.
2. Find every CSS variable in the inline style that the override touches
   (e.g. `--extracted-r6o4lv`, `--framer-text-color`, plus the visible
   `color`). Override **all of them**, not just the visible one —
   `color` is computed from `var(--framer-text-color)` via chained
   `var()` references, and the inline variable value wins if you only
   set `color`.
3. Key the selector on the variant class (`.framer-v-XXXX`), not
   `data-framer-name`.
4. Use `!important` on every override.

Worked example for a "Solid Black" button label color:

```css
.framer-XXXXX.framer-v-12dzqzc .framer-1t3u5p4,
.framer-XXXXX.framer-v-12dzqzc .framer-1t3u5p4 p {
  color: rgb(255, 255, 255) !important;
  --extracted-r6o4lv: rgb(255, 255, 255) !important;
  --framer-text-color: rgb(255, 255, 255) !important;
}
```

---

**Runtime re-writes inline styles, defeating author CSS overrides.**

If you write a CSS override with `!important` and it visibly applies
for a frame then snaps back, the Framer runtime is re-writing the
inline style on every render cycle. Properties commonly affected:
`backdrop-filter`, `mask`, `background-color`, `overflow`,
`will-change`, `--extracted-*` / `--framer-text-color` variables.

Fix with a `MutationObserver` watching only the `style` attribute on
the targeted element:

```tsx
useEffect(() => {
  const el = document.querySelector<HTMLElement>(".framer-1a4zuki");
  if (!el) return;
  const strip = () => {
    el.style.backdropFilter = "none";
    el.style.webkitBackdropFilter = "none";
    el.style.mask = "none";
    el.style.background = "transparent";
  };
  strip();
  const mo = new MutationObserver(strip);
  mo.observe(el, { attributes: true, attributeFilter: ["style"] });
  return () => mo.disconnect();
}, []);
```

Use `attributeFilter: ["style"]` to keep the cost negligible. Tear
down on unmount. This is the only reliable counter for properties the
runtime claims ownership of. The `useStripFramerStyles` utility
shipped with this export packages this pattern as a reusable hook.

**`utils/LayoutIsland.tsx`:**

```tsx
/**
 * LayoutIsland
 *
 * Wraps any Framer-exported component (or group of them) in its own
 * isolated framer-motion LayoutGroup so internal `layoutId` props
 * cannot collide with siblings in another part of the tree.
 *
 * Why this is needed:
 *   Bundled Framer components contain string-literal `layoutId` props
 *   on motion nodes. The exporter prefixes those ids per-component
 *   (so a Badge inside Stack and a Badge inside Center no longer
 *   share `layoutId="eTnAKyjwo"`). But if the consumer mounts the
 *   SAME component multiple times on one page — three Badges inside
 *   a Stack, say — framer-motion's shared-layout machinery still
 *   picks one as the "live" instance and animates the rest to ghost
 *   positions with opacity: 0. The text disappears.
 *
 *   LayoutIsland blocks that by giving every wrap its own
 *   LayoutGroup id (via React.useId()) and setting
 *   `inherit={false}` so the inner group doesn't merge with any
 *   outer LayoutGroup.
 *
 * IMPORTANT LIMIT — INNER-SIBLING COLLISIONS:
 *   LayoutIsland isolates *across* component imports. It does NOT
 *   solve collisions when a single exported component renders N
 *   copies of an internal sub-component (e.g. `Stack` rendering
 *   three internal `Badge` instances; `FAQ List` rendering six
 *   internal items). Those N sub-components share the same prefixed
 *   layoutId inside Stack's own internal LayoutGroup, so 1 stays
 *   visible and the other N−1 ghost.
 *
 *   When you see this symptom — a Stack/List of N items where
 *   only one renders its text — apply the CSS escape-hatch on the
 *   ghosted nodes:
 *
 *     .ghosted-class {
 *       opacity: 1 !important;
 *       transform: none !important;
 *       pointer-events: auto !important;
 *     }
 *
 *   You can identify ghosted nodes in devtools: they have inline
 *   `transform: translate3d(Xpx, Ypx, 0px) scale(...)` plus
 *   `opacity: 0` on what should be visible text. This costs the
 *   shared-layout animation between siblings (which was the point
 *   of the inner LayoutGroup) but recovers the visible content
 *   (which is what the user actually needs).
 *
 * Usage:
 *
 *   import LayoutIsland from "./utils/LayoutIsland";
 *
 *   <LayoutIsland>
 *     <Stack />     {/* Stack renders 3 Badges internally — all isolated *​/}
 *   </LayoutIsland>
 *
 *   <LayoutIsland>
 *     <Center />    {/* separate island — Badge inside Center won't collide *​/}
 *   </LayoutIsland>
 */
"use client";
import { LayoutGroup } from "framer-motion";
import { useId, type ReactNode } from "react";

export default function LayoutIsland({ children }: { children: ReactNode }) {
  const id = useId();
  return (
    <LayoutGroup id={id} inherit={false}>
      {children}
    </LayoutGroup>
  );
}
```

**`utils/useStripFramerStyles.ts`:**

```ts
/**
 * useStripFramerStyles
 *
 * React hook that strips specified inline-style properties from a
 * target element on mount and re-strips them whenever the Framer
 * runtime re-applies them.
 *
 * Why this is needed:
 *   The Framer runtime claims ownership of certain inline-style
 *   properties (backdrop-filter, mask, background, overflow,
 *   will-change, --extracted-* CSS variables) and re-writes them on
 *   every render cycle — even without an active animation. Inline
 *   `style="..."` always beats external `!important` in the CSS
 *   cascade, so any author override applies for one frame then snaps
 *   back. There is no CSS-only counter.
 *
 *   The MutationObserver below watches the target's `style` attribute
 *   and re-strips the properties every time the runtime touches them.
 *   `attributeFilter: ["style"]` keeps the observer cost negligible.
 *
 * Usage:
 *
 *   import useStripFramerStyles from "./utils/useStripFramerStyles";
 *
 *   function HeaderFix() {
 *     useStripFramerStyles(".framer-1a4zuki", [
 *       "backdropFilter",
 *       "webkitBackdropFilter",
 *       "mask",
 *       "background",
 *     ]);
 *     return null;
 *   }
 *
 *   // Then mount <HeaderFix /> once at the page root.
 */
"use client";
import { useEffect } from "react";

type StyleProperty = keyof CSSStyleDeclaration;

/**
 * Watch `selector`'s `style` attribute and clear each named property
 * whenever the runtime sets it. Cleared properties are set to "none"
 * (for filter/mask family) or "" (for color/background family) — the
 * sensible neutral value for each.
 *
 * Tears down the observer on unmount.
 */
export default function useStripFramerStyles(
  selector: string,
  properties: string[],
): void {
  useEffect(() => {
    const el = document.querySelector<HTMLElement>(selector);
    if (!el) return;
    const strip = () => {
      for (const prop of properties) {
        // For filter/mask family: explicit "none" defeats runtime values.
        // For background family: "" lets CSS take over.
        const neutral = /filter|mask|overflow|will/i.test(prop) ? "none" : "";
        // @ts-expect-error — dynamic style key set.
        el.style[prop as StyleProperty] = neutral;
      }
    };
    strip();
    const mo = new MutationObserver(strip);
    mo.observe(el, { attributes: true, attributeFilter: ["style"] });
    return () => mo.disconnect();
  }, [selector, properties.join(",")]); // eslint-disable-line react-hooks/exhaustive-deps
}
```

**`utils/FramerEffects.tsx`:**

```tsx
/**
 * FramerEffects — auto-populated by the exporter
 *
 * The bundled Framer runtime's withFX HOC does NOT execute the
 * `__framer__*` animation props it receives. This file
 * reimplements those animations via WAAPI so the rendered
 * components actually animate.
 *
 *
 * NOTE: 5 effect targets were detected but not auto-populated below.
 * You'll need to populate them manually following the discovery loop:
 *   - .framer-styles-preset-1couuo6 (__framer__styleAppearEffectEnabled): transition is a spring — pre-sampling not auto-extracted (see Discovery Loop)
 *   - .framer-styles-preset-1couuo6 (__framer__styleAppearEffectEnabled): transition is a spring — pre-sampling not auto-extracted (see Discovery Loop)
 *   - .framer-styles-preset-1couuo6 (__framer__styleAppearEffectEnabled): transition is a spring — pre-sampling not auto-extracted (see Discovery Loop)
 *   - .framer-styles-preset-1couuo6 (__framer__styleAppearEffectEnabled): transition is a spring — pre-sampling not auto-extracted (see Discovery Loop)
 *   - .framer-styles-preset-1couuo6 (__framer__styleAppearEffectEnabled): transition is a spring — pre-sampling not auto-extracted (see Discovery Loop)

 * Mount this component once at the page root.
 */
"use client";
import { useEffect } from "react";

interface RevealSpec {
  selector: string;
  keyframes: Keyframe[];
  duration: number;
  easing?: string;
  threshold?: number;
  once?: boolean;
}

interface LoopSpec {
  selector: string;
  keyframes: Keyframe[];
  duration: number;
  easing?: string;
  pauseOffscreen?: boolean;
}

const REVEAL_SPECS: RevealSpec[] = [];

const LOOP_SPECS: LoopSpec[] = [];

export default function FramerEffects() {
  useEffect(() => {
    const cleanups: Array<() => void> = [];
    const fired = new Set<Element>();

    for (const spec of REVEAL_SPECS) {
      const targets = document.querySelectorAll<HTMLElement>(spec.selector);
      if (targets.length === 0) continue;
      targets.forEach((el) => {
        const initial = el.animate(spec.keyframes.slice(0, 1) as Keyframe[], { duration: 1, fill: "forwards" });
        initial.pause();
      });
      const io = new IntersectionObserver((entries) => {
        for (const e of entries) {
          if (!e.isIntersecting) continue;
          if (spec.once !== false && fired.has(e.target)) continue;
          (e.target as HTMLElement).animate(spec.keyframes, {
            duration: spec.duration,
            easing: spec.easing,
            fill: "forwards",
          });
          if (spec.once !== false) fired.add(e.target);
        }
      }, { threshold: spec.threshold ?? 0, rootMargin: "0px" });
      targets.forEach((el) => io.observe(el));
      cleanups.push(() => io.disconnect());
    }

    for (const spec of LOOP_SPECS) {
      const targets = document.querySelectorAll<HTMLElement>(spec.selector);
      const anims: Animation[] = [];
      targets.forEach((el) => {
        const anim = el.animate(spec.keyframes, {
          duration: spec.duration,
          easing: spec.easing,
          iterations: Infinity,
        });
        anims.push(anim);
      });
      if (spec.pauseOffscreen) {
        const io = new IntersectionObserver((entries) => {
          for (const e of entries) {
            const i = Array.from(targets).indexOf(e.target as HTMLElement);
            if (i < 0) continue;
            if (e.isIntersecting) anims[i]?.play();
            else anims[i]?.pause();
          }
        }, { threshold: 0 });
        targets.forEach((el) => io.observe(el));
        cleanups.push(() => io.disconnect());
      }
      cleanups.push(() => anims.forEach((a) => a.cancel()));
    }

    return () => cleanups.forEach((fn) => fn());
  }, []);

  return null;
}
```

**`utils/ResponsiveWrapper.tsx`:**

```tsx
/**
 * ResponsiveWrapper
 *
 * Wraps a Framer-exported component with multi-variant support
 * (Desktop / Tablet / Phone / etc.) and automatically picks the
 * appropriate variant based on the viewport width.
 *
 * Why this is needed:
 *   Framer-exported components render at their canvas-time width
 *   (typically 1200px or 1920px) and don't auto-switch variants on
 *   resize. The consumer has to wire viewport-based variant
 *   selection by hand for every multi-variant component.
 *
 *   This wrapper takes a Component + variants map and watches
 *   `window.matchMedia` for breakpoint changes, passing the right
 *   `variant` prop down on each viewport.
 *
 * Usage:
 *
 *   import ResponsiveWrapper from "./utils/ResponsiveWrapper";
 *   import Header from "./Header";
 *
 *   <ResponsiveWrapper
 *     Component={Header}
 *     variants={{
 *       base: "Phone",     // 0+
 *       md: "Tablet",      // 810+
 *       lg: "Desktop",     // 1200+
 *     }}
 *   />
 *
 * Breakpoints follow the responsive-runtime defaults (Framer's own
 * canvas breakpoints).
 */
"use client";
import { useEffect, useState, type ComponentType } from "react";

interface ResponsiveWrapperProps<P extends { variant?: string }> {
  Component: ComponentType<P>;
  variants: {
    base?: string;
    sm?: string;
    md?: string;
    lg?: string;
    xl?: string;
    "2xl"?: string;
  };
  // Any other props get forwarded as-is.
  [key: string]: unknown;
}

const BREAKPOINTS = {
  base: 0,
  sm: 390,
  md: 810,
  lg: 1200,
  xl: 1440,
  "2xl": 1920,
} as const;

function pickVariant(
  width: number,
  variants: ResponsiveWrapperProps<{ variant?: string }>["variants"],
): string | undefined {
  const order: Array<keyof typeof BREAKPOINTS> = ["2xl", "xl", "lg", "md", "sm", "base"];
  for (const bp of order) {
    if (width >= BREAKPOINTS[bp] && variants[bp]) {
      return variants[bp];
    }
  }
  return variants.base;
}

export default function ResponsiveWrapper<P extends { variant?: string }>({
  Component,
  variants,
  ...rest
}: ResponsiveWrapperProps<P>) {
  const [variant, setVariant] = useState<string | undefined>(() => {
    if (typeof window === "undefined") return variants.lg ?? variants.base;
    return pickVariant(window.innerWidth, variants);
  });

  useEffect(() => {
    if (typeof window === "undefined") return;
    const onResize = () => setVariant(pickVariant(window.innerWidth, variants));
    onResize();
    window.addEventListener("resize", onResize);
    return () => window.removeEventListener("resize", onResize);
  }, [variants]);

  return <Component {...(rest as unknown as P)} variant={variant} />;
}
```
